# 产品发布工作台

一个面向 SuperAgent 教程的独立教学副本：六张发布卡片，按待开始、进行中、待确认、已完成四列整理。可以真实拖动卡片；没有后台、额外账号、模型接口或外部数据服务。

界面与拖放代码取自 [Studio Admin](https://github.com/arhamkhnz/next-shadcn-admin-dashboard) 的 Kanban，固定提交 `036631eb6896817649272fe79ded8c80faa709ee`，按 MIT 许可保留版权。原始相关文件位于 `sources/studio-admin/`，具体对应与哈希见 [来源记录](docs/上游来源锁定.json)。这里只提取了本次看板需要的代码，不运行整套管理后台。

## 本地打开

使用 Node.js 24 或更高版本：

```bash
npm ci
npm run dev
```

打开终端返回的本机地址，默认 `http://127.0.0.1:57816/`。

`npm run build` 生成静态文件到 `dist/`；`npm run preview` 可检查构建结果。相对资源路径已设置，可以发布到 GitHub Pages 子目录。

## 使用说明

- **更新进度**：把卡片拖到目标列即可，刷新页面后位置会保留（状态保存在浏览器本地）。
- **生成发布清单**：点击发布看板工具栏的「生成发布清单」按钮，页面会列出所有未完成事项，含负责人与截止时间，点一下文字即可全选复制给团队。已完成（「已完成」列）的事项不会列入；若全部完成，则显示「已经全部准备好了，可以发布」。清单只在本页显示，不会自动发送任何消息；清单内容随当前看板状态更新，点「关闭」可收起。

## 这份基线保留的问题

把“演示视频”从“进行中”拖到“待确认”，本页会显示移动成功；刷新后又回到“进行中”。这是为本教程明确保留的教学故障，不声称上游产品存在同样的缺陷；本 PR 已修复，刷新后位置会保留。

运行 `npm test`，两项检查均通过：其中“重新打开后仍保留新位置”是基线保留的复现测试，修复后转为通过；“只移动当前卡片，其他卡片不受影响”用于保证其它卡片状态不变。发布清单另有独立测试。测试调用的内存状态模块，也正是页面拖放时调用的模块；这些检查都保留，未删除或跳过。
